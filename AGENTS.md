# AGENTS.md

Working notes for agents building/testing this port. See
`docs/DEVELOPMENT.md` for the project's own description; this file records the
debugging gotchas that are easy to relearn the hard way.

## Building

Expansion (the default target for this work):

```sh
make -C build/expansion/3ds_port -j8 PYTHON=python3
```

Vanilla (keep it working too): `make -C build/upstream/3ds_port ...`.

The dev `.3dsx` is ~30 MB because it embeds the data. `build/expansion` is a
git checkout of the pinned expansion commit plus the port; `3ds_port/` and
`tools/` at the repo root are the canonical copies and bootstrap places them
into the build trees. So:

- **Port changes** go in the repo-root `3ds_port/`, `tools/`, `builder/`.
- **Game-tree changes** are made in `build/expansion/` and then captured in the
  patch (below).

`make` builds from the **build tree's** copy (`build/expansion/3ds_port/...`),
so a repo-root port edit does nothing until it is synced there:

```sh
cp 3ds_port/src/voxel/ctr_voxel.c build/expansion/3ds_port/src/voxel/
```

Re-running `tools/bootstrap.py` also copies the port, but it resets the game
tree when the patch digest changed, which discards uncommitted game-side debug
edits - during iteration, `cp` the specific files instead. A port `Makefile`
flag change does relink; a port `.c` change recompiles. Watch for the
`-DEMERALD`-style trap: the port recompiles the game sources with its own
flags, so anything the game Makefile passed via `-D$(GAME_VERSION)` must be
repeated in `3ds_port/Makefile`'s `GAMEFLAGS` (missing `EMERALD` silently
emptied `gWildMonHeaders`).

Game translation units have no header dependency tracking: after editing a
shared header, delete the affected `build/root/src/*.o`. Under `-j8` the
asset-table step occasionally writes 0 entries (a race with the on-demand
asset generation); if `romfs/assets/asset_map.txt` is tiny, re-run `make`
(or `-j1`) rather than deploying that build.

## Regenerating the expansion patch

`patches/pokeemerald-expansion/0001-port.patch` is a single squashed diff from
the pinned upstream commit (`dfb0f843`, post-1.17.1; see `upstream.lock`) to the current
`build/expansion` working tree, with a 3-line header and `c/`/`w/` prefixes:

```sh
cd <repo root>
# NOTE: `git diff` alone SILENTLY DROPS the port's new files (they are
# untracked in the build tree: include/cgb_audio.h, src/platform/*, etc.).
# Regenerating without them produces a patch that builds fine on the current
# tree but breaks the next fresh bootstrap (Oct 2026: 17 files lost this way).
# Stage new files explicitly first, excluding everything bootstrap copies
# separately (3ds_port/, builder/, tools/, upstream.lock) plus build outputs
# and generated files, then diff the index:
git -C build/expansion add -A ':!3ds_port' ':!builder' ':!tools' ':!upstream.lock' \
  ':!.emerald3ds-patches' ':!build' ':!*.o' ':!*.bin' \
  ':!data/maps/*/*.inc' ':!sound/songs/*.s'
git -C build/expansion diff --cached --src-prefix=c/ --dst-prefix=w/ dfb0f843 > /tmp/body.patch
{ printf '%s\n' \
  "Pokemon Emerald 3Ds Dual Screen changes to rh-hideout/pokeemerald-expansion post-1.17.1 (dfb0f84374230f4d462191601179b742f9f077df)." \
  "Generated by tools/bootstrap.py; apply with tools/bootstrap.py --upstream pokeemerald-expansion." \
  ""; cat /tmp/body.patch; } > patches/pokeemerald-expansion/0001-port.patch
```

Untracked `3ds_port/`, `builder/`, `tools/` are intentionally *not* in the
patch (bootstrap copies them separately). Use the staged diff above so new
game-side files remain in the patch.

Verify both directions before committing:

```sh
# 1. Patch exactly matches the working tree (reverse-apply from current state):
git -C build/expansion apply --check --reverse patches/pokeemerald-expansion/0001-port.patch

# 2. Patch applies to a clean upstream checkout:
git -C build/expansion worktree add --detach /tmp/exp-check dfb0f843
git -C /tmp/exp-check apply --check <abs path to patch>
git -C build/expansion worktree remove --force /tmp/exp-check
```

## Debugging gotchas (expansion port)

- **`CreateSprite` reads animation 0 before `StartSpriteAnim`.** The expansion's
  shared category icon table originally put NULL at index `DAMAGE_CATEGORY_NONE`
  (0). Dump `crash_dump_00000038.dmp` crashed in `SetSpriteSheetFrameTileNum`
  while opening summary move details; battle move details, the move relearner,
  and HGSS Pokédex share the template. Give slot 0 a valid frame on 3DS.
  `make verify` now exercises real sprite creation/animation and audits every
  linked animation table, including implicit enum holes. Audit
  `build/gamedata_image.elf`, whose `.gamedata` is PROGBITS; the shipped ELF
  reserves it as NOBITS, so reading its file bytes gives false null pointers.
- **Animation and form-change helpers also run outside battles.** Expansion's
  `Task_HandleMonAnimation` completes during evolution, egg hatching, contests,
  and Hall of Fame scenes; guard its KO counter access when `gBattleStruct`
  is NULL. Hardware evolution dump `crash_dump_00000037.dmp` identified this
  access (PC `0x00383064` in the October 17 build). Likewise,
  `GetBattlerPartyStateByPokemon` must return NULL without battle resources:
  overworld time, item, daycare, and poison form changes call it too. Never
  form `&gBattleStruct->partyState[...]` from a NULL allocation. Regression:
  `python3 3ds_port/tests/evolution_animation_test.py --tree build/expansion`.
- **The assembler never saw `-DTESTING=0`.** C files get it via GAMEFLAGS, but
  `ASFLAGS` had no `--defsym TESTING=0` and CPPTOOL gets no `-D` flags, so GAS
  evaluated `.if TESTING == FALSE` (guards every cry sample in
  `sound/direct_sound_data.inc`) with TESTING undefined - and GNU as *silently
  drops* such blocks with exit 0. Every `Cry_X` label landed on one address:
  total cry silence. Fixed by adding `--defsym TESTING=0` to ASFLAGS in
  `3ds_port/full.mk`. Proven in the 3dsx: 1159/1159 distinct cry pointers
  after, 1/1159 before. If audio data ever goes missing again, scan the
  binary for the expected table pattern before blaming the mixer.
- **`mapjson map` must run from the tree root.** It reads
  `include/constants/map_groups.h` via a cwd-relative path, but the port runs
  `gen_missing_map_includes.py` from `3ds_port/`; every map then fails one at
  a time (looks like a race, is not). `full.mk` now `cd`s to `$(ROOT)` with
  absolute paths for both the stamp rule and `map-includes`.


- **`AllocSpriteTiles(0)` means "free every tile", not "allocate zero".** A
  sprite sheet that loads with a tile count of 0 silently frees all other
  sprites' tiles. Externalized assets that fail to resolve remain tiny stubs,
  so `sizeof(stub)` is often 1; `1 / TILE_SIZE_4BPP == 0` then triggers the
  free-all. `LoadSpriteSheetWithOffset` must guard `sheetSize <
  TILE_SIZE_4BPP` (and `<= offset`) and bail. This was the cause of the garbled
  battle foreground: bogus gimmick-indicator sheets (tags `0xDEDE`+) freed the
  healthbox tile ranges, and battlers then reused tiles 0–159.
- `LoadCompressedSpriteSheet` must honor a nonzero declared `src->size`, capped
  at the **decompressed** length. Some healthboxes declare more than the data;
  health bars deliberately use only 0x100/0x120 bytes of a shared 0x800 blank
  asset. Using the full asset for four bars wastes 222 OBJ tiles and hangs the
  Mossdeep partner battle during send-out. Regression: `verify-compressed-sheet`.
- `gen_asset_table.py` scans `ROOT/src` where `ROOT` is the build tree (e.g.
  `build/expansion`). It generates `build/assets/...` on demand; some expansion
  assets (e.g. gimmick indicator PNGs) are not produced and land in the "stub
  size" path above. This is a known, currently-harmless gap.
- Known harmless log errors: `singular affine BG matrix`, `OBJ windows not
  supported`, `BG mosaic not supported`, missing mega/gmax/indicator assets.
- Use the game's own `PORT_LOG`/`CtrLog_Write` markers for tracing, then strip
  the instrumentation before regenerating the patch. Keep a `git -C
  build/expansion status` / diff habit so debug edits don't leak into the
  patch.
